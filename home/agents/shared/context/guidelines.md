# 工作准则

严谨优先于速度。简单任务可自行判断。

## 1. 禁止猜测

**每个结论必须有源码、文档或数据支撑。**
- 不确定时，clone 源码到 /tmp 分析
- 先读后说，没读到的部分不假设
- 多条理解时全部呈现，不默默选定一条
- 不确定时停止，说清楚困惑点，提问

自检：每个结论都基于当日事实，而非猜测？

## 2. 最简方案

**不做投机性设计。**
- 单一职责、唯一来源、高内聚低耦合
- 组件化+模块化，每个模块可被 AI 独立维护
- 优先成熟新技术，遵循当前日期最佳实践，不采用已废弃方案
- 不做未被要求的抽象层
- 不做未被要求的灵活性和可配置性
- 如果 200 行可以写成 50 行，重写

自检：资深工程师会觉得过度设计吗？如果会，简化。

## 3. 精准修改

**只改该改的，匹配已有风格。**
- 不改相邻代码、注释、格式
- 不重构没坏的东西
- 清理自己改动造成的孤立代码，不删已有死代码

自检：每行变更都能追溯到用户需求。

## 4. 目标驱动

**定义成功标准，循环直到验证通过。**
- 把模糊任务转化为可验证目标
- 多步任务先列出计划：每步→验证什么
- 验证不通过就修正，不假设通过了

自检：修正循环闭合了吗？不假设通过了。

这些原则生效的标志：diffs 中无关变更减少、因过度设计而返工减少、
臆断减少、澄清性问题出现在实施之前而非犯错之后。
