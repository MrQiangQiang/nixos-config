
skill 的存在是为了从随机系统中获取确定性。**可预测性**——agent 在每次运行中采取相同的_过程_，而非产生相同的输出——是根本美德；下面的每个杠杆都服务于它。

**加粗术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中有定义；在那里查找完整含义。

## 调用

两种选择，权衡不同的成本：

- **模型调用**的 skill 保留**描述**，因此 agent 可以自主触发它_并且_其他 skill 可以到达它（你仍然可以输入它的名字）。它增加**上下文负载**——描述每个回合都驻留在窗口中。机制：省略 `disable-model-invocation`，并编写一个面向模型的描述，包含丰富的触发短语（"当用户想要……、提到……时使用"）。
- **用户调用**的 skill 从 agent 的可达范围中剥离描述：只有你，输入它的名字，才能调用它——且没有其他 skill 可以。零上下文负载，但它消耗**认知负载**：_你_就是必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变为面向人类——一行摘要，去掉触发列表。

仅当 agent 必须自行到达该 skill，或另一个 skill 必须到达它时，才选择模型调用。如果它只通过手动触发，就设为用户调用，不付出任何上下文负载。

当用户调用的 skill 多到你记不住时，这种堆积的认知负载由**路由 skill**来解决：一个用户调用的 skill，命名其他 skill 以及何时使用每一个。

## 编写描述

模型调用的**描述**做两件事——说明 skill 是什么，以及列出应该触发它的**分支**。每个词都增加**上下文负载**，所以描述比正文更需要强力修剪：

- **前置 skill 的引导词**——描述是它执行调用工作的地方。
- **每个分支一个触发器。** 重命名单个分支的同义词是**重复**——"使用 TDD 构建功能……要求测试优先开发"是一个分支写了两次。合并它们；只保留真正不同的分支。
- **删掉正文已有的标识。** 描述只保留触发器，以及任何"当另一个 skill 需要……"的到达条款。

## 信息层次

skill 由两种内容类型构建——**步骤**和**参考**——它们自由混合：一个 skill 可以全是步骤、全是参考，或两者都有。核心决策是使用哪种以及每种在**信息层次**上的位置，这是一个按 agent 需要材料的紧迫程度排序的阶梯：

1. **skill 内步骤**——`SKILL.md` 中的有序操作，主要层级：agent 按顺序做什么。每个步骤以一个**完成标准**结束，即告诉 agent 工作已完成的条件。使其_可检查_（agent 能区分完成与未完成吗？）且在重要的地方_穷尽的_（"每个修改的模型都被考虑"，而非"产生一个变更列表"）——模糊的标准会导致**过早完成**。
2. **skill 内参考**——`SKILL.md` 中的定义、规则或事实，按需查阅。通常是合理的扁平对等集（一次审查的所有规则在同一层级）——这是一种好的安排，不是问题。_此 skill 全是参考。_
3. **外部参考**——从 `SKILL.md` 推出到单独文件中的参考，通过**上下文指针**到达，仅在指针触发时加载。（从_披露的_参考——像 `GLOSSARY.md` 这样的同级文件，仍是 skill 的一部分——到完全在 skill 系统之外的**外部参考**，任何 skill 都可以指向它。）

要求高的完成标准驱动彻底的**基础工作**——agent 在工作内所做的挖掘——无论 skill 是否有步骤，因为"每条规则都已应用"约束扁平参考，就像"每个步骤都已完成"约束一个序列。

向下推得太少，顶部就会膨胀；推得太多，你就会隐藏 agent 实际需要的材料。这种张力就是整个决策。

**渐进式披露**是沿着阶梯向下移动——从 `SKILL.md` 到一个链接文件——使顶部保持可读。机制：skill 文件夹中一个链接的 `.md` 文件，以其内容命名（此 skill 将其完整定义披露到 `GLOSSARY.md`）。一些 skill 以多种方式使用，每种不同的方式是一个**分支**——不同的运行通过 skill 的不同路径。分支是最清晰的披露测试：内联每个分支都需要的内容，将只有某些分支到达的内容推到指针后面。**上下文指针**的_措辞_，而非其目标，决定了 agent 何时以及以多大可靠性到达该材料。

阶梯决定了一个内容_位于多深_，而**共置**决定了_什么与它并列_：将一个概念的定义、规则和注意事项放在一个标题下，而非分散，这样阅读一部分就能将其邻近内容一起带来。

## 何时拆分

**粒度**是你划分 skill 的精细程度，每次切割都消耗两种负载之一，所以仅在切割值得时才拆分。两种切割：

- **按调用**——当你有一个独特的**引导词**应该自行触发它，或另一个 skill 必须到达它时，拆分出一个**模型调用**的 skill。你为新始终加载的**描述**付出**上下文负载**，所以独立的到达必须值得。
- **按序列**——当接下来的步骤（一个步骤的**完成后步骤**）诱惑 agent 急于完成当前步骤时（**过早完成**），拆分一连串**步骤**。将它们排除在视野之外，鼓励 agent 在当前任务上做更多**基础工作**。

## 修剪

将每个含义保留在**单一真相源**中：一个权威位置，这样更改行为就是一处编辑。

检查每一行的**相关性**：它是否仍然与 skill 做的事情有关？

然后逐句搜寻**空操作**，而非仅逐行：对每个句子单独运行空操作测试，当一个句子失败时，删除整个句子而非从中修剪词语。要激进——大多数失败的散文应该删除，而非重写。

## 引导词

**引导词**是一个已经存在于模型预训练中的紧凑概念，agent 在运行 skill 时用它来思考（例如_课程_、_战争迷雾_、_示踪子弹_）。在文本中重复出现（尽管不一定——一个强引导词可能只需一次），它积累一个分布式定义，并通过调用模型已有的先验，用最少的 token 锚定一整片行为区域。

它两次服务于可预测性。在正文中它锚定_执行_：每当该词出现时，agent 都会采取相同的行为。在描述中它锚定_调用_：当同一个词出现在你的提示、文档和代码中时，agent 将这种共享语言链接到 skill 并更可靠地触发它。

寻找机会重构 skill 以使用引导词。在三个地方拼出的三合体（**重复**），一个用一句话指向一个想法的描述——每段都是乞求**合并**成单个 token 的段落。示例包括：

- "快速、确定性、低开销" -> _紧凑_——一个在某个阶段重述的品质——变成一个预训练的词（一个_紧凑_的循环）。
- "你相信的循环" -> _红色_——将模糊的门转换为二元可观察状态（循环在 bug 上变_红_，或不变）。

你两次获胜：更少的 token，_以及_一个更锐利的钩子供 agent 挂载其思考。假设每个 skill 都带有引导词可以退休的重述——去找它们。

## 失败模式

使用这些来诊断用户可能遇到的 skill 问题。

- **过早完成**——在真正完成之前结束一个步骤，注意力滑向_已完成_。防御，按顺序：首先磨利完成标准（廉价、局部）；只有当它不可减少地模糊_且_你观察到急躁时，才通过拆分（序列切割）隐藏完成后的步骤。
- **重复**——同一含义出现在多个地方。消耗维护和 token，并在阶梯上夸大一个含义的显要程度，超过其真实排名。
- **沉积**——因为添加感觉安全而移除感觉有风险而沉淀的过时层。任何没有修剪纪律的 skill 的默认命运。
- **蔓延**——一个 skill 单纯太长，即使每一行都是活跃且唯一的。损害可读性和可维护性并浪费 token。治愈方法是阶梯：将**参考**披露到指针后面，并按**分支**或序列拆分，使每条路径只携带它需要的内容。
- **空操作**——模型默认已经遵守的一行，所以你付出负载什么也没说。测试：它是否改变行为相对于默认？弱引导词（当 agent 已经偏彻底时说_要彻底_）是空操作；修复是一个更强的词（_不留余地_），而非不同的技术。
- **否定**——通过禁止来引导会适得其反：_不要想大象_命名了大象并使它更可及，而非更少。提示**正面**——陈述目标行为，使被禁止的行为永远不被说出；仅在你无法用正面表达的硬护栏上保留禁止，即便那时也将其与应该做什么配对。
