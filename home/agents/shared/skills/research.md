# 研究调研

对技术方案、工具选型、框架对比、最新动态等进行系统性调研。跨 agent 通用（OpenCode/Claude Code/Codex/Trae）。

触发条件：用户说"调研""研究""对比""选型""最新的""look up""research""compare"等。

## Step 0: 工具可用性预检

在执行调研前，确认当前 agent 可用的搜索工具：

| 检查项 | OpenCode | Claude Code / Codex / Trae |
|--------|----------|---------------------------|
| 全网搜索 | `websearch`（内建，免费） | `parallel-search` MCP |
| 网页抓取 | `webfetch`（内建） | `parallel-search` MCP (web_fetch) |
| 官方文档 | `context7` MCP | `context7` MCP |
| 本地知识库 | `qmd` MCP | `qmd` MCP |
| 子代理并行 | `task` (general subagent) | subagent (agent 支持时) |

如果某工具不可用，在报告中注明，改用可用的替代工具。不要尝试调用不存在的工具。

## Step 1: 评估需求 → 选择路径

根据问题复杂度选择调研深度，避免为简单问题启动重型流程：

**快速查证**（1 个事实性问题）：
→ 单次 `websearch` 或 `parallel-search` → 直接回答，附来源

**标准调研**（对比/选型，2-4 个子问题）：
→ 完整流程：拆解 → 搜索 → 深读 → 综合 → 输出

**深度调研**（需要 5+ 来源、交叉验证）：
→ 标准流程 + 子代理并行 + 多轮搜索迭代

## Step 2: 拆解问题

将调研目标分解为 3-5 个独立子问题。示例：
- 主题："2026 年 Rust vs Go 后端选型"
  - Rust 后端生态最新状态（框架、ORM、部署）
  - Go 后端生态最新状态
  - 性能/并发模型对比
  - 团队学习成本与招聘市场
  - 各场景（API/微服务/CLI）适合哪个

**门控**：进入 Step 3 前，必须输出子问题列表。如果无法列出 3 个以上子问题，说明问题太简单，改用快速查证路径。

## Step 3: 并行搜索

每个子问题用 2-3 个不同措辞搜索：

- **全网搜索**：`websearch("Rust backend frameworks 2026")` / `parallel-search`
- **官方文档**：`context7` 查最新 API/breaking changes
- **本地知识库**：`qmd` 查之前是否有相关调研

目标：每个子问题至少 3 个来源，总计 15-30 个独立来源。

**门控**：进入 Step 4 前，检查是否已为每个子问题找到至少 2 个来源。某子问题来源不足时，换措辞重搜，不要带着空洞进入深读。

## Step 4: 深读关键来源

对最有价值的 URL，用 `webfetch` 或 MCP web_fetch 获取全文。不要仅依赖搜索摘要。至少深读 3-5 篇核心来源。

## Step 5: 综合与输出

### 必须区分证据类型

每个结论标注证据等级：
- `[来源]` — 有公开 URL 支撑的事实
- `[用户提供]` — 用户在对话中给出的上下文
- `[推断]` — 从证据推导的结论
- `[建议]` — 主观推荐

### 输出模板

```markdown
# [主题]：调研报告
*日期：[date] | 来源数：[N] | 深读：[M] 篇 | 可信度：[高/中/低]*

## 要点摘要
[3-5 句话概括核心发现]

## 1. [第一个维度]
- 核心发现 ([来源]：source1)
- 补充数据 ([来源]：source2)
- 分析结论 ([推断])

## 2. [第二个维度]
...

## 关键结论
- [建议] 可操作的推荐
- [推断] 趋势判断

## 来源列表
1. [Title](url) — 一句话摘要
2. ...

## 方法说明
搜索关键词：[list]，子问题：[list]，并行子代理数：[N]
```

### 交付规则

- **短报告**（<500 字）：直接在对话中输出完整报告
- **长报告**：输出要点摘要 + 关键结论，完整报告写入文件

## Step 6: 子代理并行（深度调研时使用）

对于需要多角度覆盖的大主题，用子代理并行搜索：

```text
启动 3 个搜索子代理：
1. 子代理 1：研究子问题 1-2（使用 websearch + context7）
2. 子代理 2：研究子问题 3-4（使用 websearch + context7）
3. 子代理 3：研究子问题 5 + 交叉主题（使用 websearch + qmd）

每个子代理返回结构化发现（含来源 URL）。主对话汇总为最终报告。
```

## 质量规则

1. **每个主张必须有来源。** 无来源的主张必须标注 `[推断]`
2. **交叉验证。** 只有一个来源的说法标注"待交叉验证"
3. **时效优先。** 优先最近 12 个月的内容
4. **承认未知。** 找不到好信息时直接说"未找到足够数据"
5. **不编造。** 不知道就说不知道，不要推测
6. **区分事实与意见。** 预测、估算、观点明确标注

## 模型策略

- **搜索/浏览阶段**：deepseek-v4-flash（$0.14/1M input）
- **综合/分析阶段**：deepseek-v4-pro + max reasoning（$1.74/1M input）
- 执行方式：用子代理（OpenCode `task` / 各 agent subagent）指定不同模型；无法切换时全程用 flash，在报告中注明
- 简单查证全用 flash，深度调研综合阶段切 pro

## Gotchas

- parallel-search `web_search` 摘录上限 ~25K 字符，长页面需 `web_fetch` 获取全文
- context7 免费匿名 tier 有 IP 速率限制，高频查询会触发 429
- qmd 依赖 desktop-1 在线（Tailscale mesh），离线时降级为无本地知识库
- 搜索结果可能包含过时信息，务必检查 publish_date，优先 12 个月内

## 示例

**快速查证**："调研 Vite 6 最新版 breaking changes"
→ 单次 websearch → 直接列出变化 + 来源

**标准调研**："对比 2026 年 Python 三大 Web 框架"
→ 拆解 3 子问题 → 每个搜索 3 来源 → 输出对比表

**深度调研**："调研 AI Agent 研究最前沿方案"
→ 拆解 5-6 子问题 → 3 子代理并行 → 多轮迭代 → 完整报告
