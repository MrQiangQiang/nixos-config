
# 改进代码库架构

呈现架构摩擦并提出**深化机会** — 将浅模块变为深模块的重构。目标是可测试性和 AI 可导航性。

此命令*基于*项目的领域模型，并建立在共享的设计词汇表上：

- 运行 `/codebase-design` skill 获取架构词汇表（**模块**、**接口**、**深度**、**接缝**、**适配器**、**杠杆作用**、**局部性**）及其原则（删除测试，"接口即测试面"，"一个适配器 = 假设接缝，两个 = 真接缝"）。在每条建议中精确使用这些术语 — 不要漂移到"组件"、"服务"、"API"或"边界"。
- `CONTEXT.md` 中的领域语言为好的接缝命名；`docs/adr/` 中的 ADR 记录此命令不应重新争论的决策。

## 流程

### 1. 探索

先阅读项目的领域术语表（`CONTEXT.md`）和你要触碰区域的任何 ADR。

然后用 Agent 工具以 `subagent_type=Explore` 遍历代码库。不要遵循死板的启发式 — 有机地探索并记录你体验摩擦的地方：

- 理解一个概念需要在许多小模块之间来回跳转的地方在哪里？
- 模块**浅**的地方在哪里 — 接口几乎和实现一样复杂？
- 纯函数仅为可测试性被提取出来，但真正的 bug 隐藏在它们如何被调用中（没有**局部性**）的地方在哪里？
- 紧耦合模块跨接缝泄漏的地方在哪里？
- 代码库的哪些部分未测试，或难以通过当前接口测试？

对你怀疑是浅的任何东西应用**删除测试**：删除它会集中复杂性，还是只是移动它？"是的，集中"是你想要的信号。

### 2. 以 HTML 报告呈现候选

写一个自包含的 HTML 文件到 OS 临时目录，使任何东西都不落入仓库。从 `$TMPDIR` 解析临时目录，回退到 `/tmp`（或 Windows 上的 `%TEMP%`），写到 `<tmpdir>/architecture-review-<timestamp>.html` 使每次运行得到新文件。为用户打开它 — Linux 上 `xdg-open <path>`，macOS 上 `open <path>`，Windows 上 `start <path>` — 并告诉他们绝对路径。

报告使用**通过 CDN 的 Tailwind** 做布局和样式，**通过 CDN 的 Mermaid** 做图表，当图/流/时序能可靠传达结构时使用。将 Mermaid 与手工制作的 CSS/SVG 视觉混合 — 当关系是图形状的（调用图、依赖、时序）时用 Mermaid，当你想要更编辑性的东西（质量图、截面、折叠动画）时用手工构建的 div/SVG。每个候选得到一个**前后可视化**。要视觉化。

对每个候选，渲染一张卡片，包含：

- **文件** — 涉及哪些文件/模块
- **问题** — 为何当前架构造成摩擦
- **解决方案** — 会改变什么的通俗英文描述
- **收益** — 用局部性和杠杆作用解释，以及测试将如何改善
- **前/后图** — 并排，手绘，展示浅和深化
- **推荐强度** — `Strong`、`Worth exploring`、`Speculative` 之一，渲染为徽章

报告末尾是**首要推荐**部分：你最想先解决哪个候选以及为什么。

**领域用 CONTEXT.md 词汇表，架构用 `/codebase-design` 词汇表。** 如果 `CONTEXT.md` 定义了"Order"，就说"Order intake 模块" — 不是"FooBarHandler"，也不是"Order service"。

**ADR 冲突**：如果候选与现有 ADR 矛盾，仅当摩擦真实到值得重新审视 ADR 时才呈现。在卡片中清楚标记（如警告标注：*"与 ADR-0007 矛盾 — 但值得重新开启，因为…"*）。不要列出 ADR 禁止的每个理论重构。

完整 HTML 脚手架、图表模式和样式指南见 [HTML-REPORT.md](HTML-REPORT.md)。

**暂不要提出接口。** 文件写完后，问用户："你想探索哪个？"

### 3. 盘问循环

一旦用户选定候选，运行 `/grilling` skill 与他们一起走设计树 — 约束、依赖、深化后模块的形状、接缝背后是什么、哪些测试存活。

副作用在决策结晶时内联发生 — 运行 `/domain-modeling` skill 保持领域模型最新：

- **用 `CONTEXT.md` 中没有的概念命名深化后的模块？** 将术语添加到 `CONTEXT.md`。如不存在则惰性创建文件。
- **在对话中锐化模糊术语？** 当场更新 `CONTEXT.md`。
- **用户以承载性理由拒绝候选？** 提供 ADR，措辞为：*"要我将其记录为 ADR，使未来架构审查不再重新建议它吗？"* 仅当理由确实会被未来探索者需要以避免重新建议同一东西时才提供 — 跳过短暂理由（"现在不值得"）和自明的。
- **想探索深化后模块的替代接口？** 运行 `/codebase-design` skill 并使用其 design-it-twice 并行子代理模式。
